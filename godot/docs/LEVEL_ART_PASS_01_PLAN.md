# LEVEL ART VERTICAL SLICE PASS 01 · 实施计划

## 范围与冻结项

- 只改 `player-room`、`chapel-belfry`、`low-tide-cave`、`clock-basement` 四份布局以及它们确实需要的 Godot 共享渲染/测试工具。
- 不修改其余 14 张地图布局，不触碰根目录 HTML/CSS/JavaScript/浏览器 JSON，不提交、不推送。
- 现有 manifest、atlas semantics、资产处理管线保持兼容；优先复用已生产但尚未充分使用的结构图集，本轮不启动全图资产生成。

## 执行顺序

1. 冻结 before：以 Godot 4.6.3 Compatibility 生成四张真实 1152×648 基线图和 manifest。
2. 结构先行：重画四图有效边界、平台/岩壁/设备墙和碰撞；先证明空间成立，再放物件。
3. 功能簇：每图建立至少 3 个由三个以上相关元素构成的功能区，并保留主通道 36–60px（约 1.5–2.5 角色宽）。
4. 层次与光：建立 Background/Midground/Foreground，加入按玩家位置淡出的前景结构，并把环境、主光、次光、焦点光和路径光分层。
5. 镜头：从布局读取地图专属 `camera_zoom`，player-room 1.25、belfry 1.20、cave 1.15、basement 1.15；其余地图默认 1.0。
6. 真实审查：生成 after 六视图、before/after 并排图与 contact sheet；以正常尺度检查后再迭代。
7. 功能回归：静态验证、editor import、test runner、隔离存档、正式主场景、visual smoke、四图 gallery、Compatibility、物理移动/Portal/NPC/Y 排序/碰撞。

## 四图改造蓝图

### player-room

- 把实际生活空间收成左右两个壁龛与中央短通道：左睡眠，右记录，上方壁炉/储物，下方入口过渡。
- 睡眠簇：床 + 床头柜/灯 + 小地毯 + 衣柜/窗帘；床侧保留约 32px 通道。
- 记录簇：手账桌 + 椅 + 照片板 + 行李/储物 + 工作灯；交互矩形覆盖桌面而非旧坐标。
- 壁炉簇：壁炉 + 围合墙面 + 椅/凳 + 地毯 + 局部暖光。
- 下方入口用半高隔断和门框前沿形成前景，但 Portal 中央保持清楚。

### chapel-belfry

- 关闭普通矩形 room shell，以深处为底；可走区仅由主平台、右侧维护台和左下楼台构成。
- 第七锤、锤座、支撑梁、吊绳、机械轴和校准槽组成唯一主中心。
- 高窗/维护台、下楼台/日志分别为两组次级功能簇；上方梁架不可进入。
- 使用现有 belfry 梁图集作背景立柱和前景横梁，前景在玩家靠近时降至约 35% 透明度。

### low-tide-cave

- 保留自然 shell 机制但重画强凹凸轮廓，让上方岩壁、下方水域和右侧岩体真正压缩路线。
- 删除单条平滑丝带，改成入口湿石、中央断续石面、两段木板/泥地、右侧设备台的分段路径。
- 入口、维护、隐藏证物三簇分别建立冷光、黄光和极弱证物引导光。
- 用现有 cave ceiling/wall atlas 生成上、左、右和局部下方洞顶前景，并开启近人淡出。

### clock-basement

- 中央协议台外增加六角/放射地槽；七插槽改成统一弧框并通过七条电缆连接中央。
- 红站与白站成为左右对置的结构舱，各有独立底座、垂直框、颜色光和一条明确电缆。
- 三信号灯升到后方信号桥，形成第三次级焦点；后维护台与设备壁龛收紧上半区。
- 前景管道只压画面两角，并在玩家靠近入口/站台时淡出。

## 通过门槛

- 四图正常游戏尺度整体明显改善；普通室内无功能空地不超过 30%，特殊空间留白必须承担高度/危险/仪式叙事。
- 每图至少 3 个功能区、1 主中心、2 次级组、1 主路径、1 实际前景层、1 背景边界、清楚入口/出口/交互焦点。
- 四图 overall ≥ 7.5、composition ≥ 7、spatial_density ≥ 7、gameplay_readability ≥ 8。
- 视觉与功能任一未达标时只给 `APPROVED_WITH_FIXES` 或 `REJECTED`，不以工程测试代替视觉结论。
