正式来源：`godot/`

## 量化口径

- “有效可走面积”按当前画面中被建筑/自然边界包围的可见地面计算，并扣除布局碰撞占地。矩形室内使用 `room_rect` 的实际地板区；洞穴使用 `boundary_points` 的 0.91 内轮廓并扣除水域和岩体碰撞。
- “空地比例”以 8px 网格人工复核：未被明确功能区、主路径、交互缓冲区或有叙事目的的留白覆盖的可走地面 / 有效可走面积。它不是“道具像素覆盖率”，不会奖励随机散物。
- 玩家像素高度来自正式 `spr_player.png` 的 24×48 原生帧与 1.0 相机截图；四张基线图均为 48px。
- `zones` 中原有 `foreground_zone` 只是审计元数据；没有实际前景对象时，不计为前景层。

## player-room

- 当前地图尺寸：768×480px。
- 当前有效可走面积：187,552px²（可见地板 196,392px²，扣除固定碰撞）。
- 当前空地比例：57%。中央和下半区的大块地板没有功能归属。
- 当前镜头缩放 / 玩家高度：1.00 / 48px。
- 主要视觉中心：名义上是手账桌、照片板与床，但三者分散，实际没有单一主中心。
- 次级视觉组：左侧床和床头灯；右上壁炉、衣柜与照片板。二者都未形成闭合功能簇。
- 入口和出口：下方中央 `room8_to_hall`；来自二楼的稳定出生点为 (384,405)，新游戏为 (384,370)。
- 当前功能区：睡眠、记录、储物、壁炉休息四种功能存在，但只有“类别”，没有空间组合。
- 当前物件组合：床与床头柜距离过远；手账桌、椅子、照片板不在同一操作面；壁炉缺少围合与坐席；行李、箱柜散在下半区。
- 当前前景层：0。下方 `foreground_zone` 没有任何实际遮挡资产。
- 当前光照结构：环境暖色统一铺平；壁炉暖光和床头灯存在但范围/对比不足，记录区没有工作光。
- 当前最大问题：624×410 的完整大房间把生活物件变成陈列品，入口到床/书桌/壁炉之间没有受控动线。
- 建议缩小比例：有效可走面积缩小 29%–33%，目标约 128,000–134,000px²；通过壁龛、储物墙、壁炉围合和入口隔断实现，不扩大黑边充数。
- 建议相机缩放：1.25，目标玩家约 60px 高。
- 建议新增结构：优先复用 `interior_wall_modular_set`、`interior_corner_set`、`baseboard_set` 与现有旅店家具；必要结构为内置储物墙、壁炉围合、窗台和入口隔断。本轮优先以已有图集语义拼装，不预设新增 raster asset_id。
- 必须保留的交互与稳定 ID：`repair_orders`、`player_journal`、`room8_to_hall`；睡眠/照片/物品交互的原始 landmark 数据；上述两个出生点。
- 视觉风险：暖木色同值导致家具融入地板；非整数相机缩放可能弱化像素边缘；前景隔断可能压住入口。
- 功能风险：床、桌、门的碰撞必须与新视觉对齐；从两个出生点到三处核心交互均需可达。

## chapel-belfry

- 当前地图尺寸：850×460px。
- 当前有效可走面积：191,880px²。
- 当前空地比例：64%。平台图形只改变颜色，整块矩形地板仍可走且仍被读成普通房间。
- 当前镜头缩放 / 玩家高度：1.00 / 48px。
- 主要视觉中心：`seventh_hammer` 与锤座，尺寸足够但没有梁、轴、校准槽和吊绳关系。
- 次级视觉组：左侧悬绳；右侧高窗、工具与绳圈。二者均孤立。
- 入口和出口：左下侧 `belfry_to_chapel`，来自钟厅的稳定出生点 (120,350)。
- 当前功能区：第七锤校准、维护工具、下楼三类；缺少主平台/侧台/下楼台的高度组织。
- 当前物件组合：锤与锤座重合但无结构连接；工具和绳圈在右侧散置；高窗只是一块墙面贴图。
- 当前前景层：0。没有真实横梁、立柱或近景绳索。
- 当前光照结构：高窗冷光与右侧维护灯存在，但第七锤中心暗；整图主要靠环境压暗。
- 当前最大问题：完整矩形 shell 与宽阔同高地板消除了钟楼高度、风险和维护平台语义。
- 建议缩小比例：可走面积缩小 36%–40%，目标约 116,000–123,000px²；仅保留中央主平台、侧维护台与下楼台。
- 建议相机缩放：1.20，目标玩家约 58px 高。
- 建议新增结构：复用 `belfry_timber_beam_set`、`belfry_foreground_beam_set`、`belfry_narrow_platform`、`belfry_high_window`；用语义 tile stamps 和结构多边形建立主平台、支柱、上方梁架、锤架连接与深处背景。
- 必须保留的交互与稳定 ID：`seventh_hammer`、`chapel_install_log`、`room7_tag_pickup`、`belfry_to_chapel`；音叉安装/维修状态语义；出生点 (120,350)。
- 视觉风险：开放边缘必须与可走区有明显值差；前景横梁不能长期遮住锤和玩家；现有梁图集是 32px 模块，重复节奏需打破。
- 功能风险：左侧出生和下楼 Portal 需要留出 1.5–2.5 人宽通道；锤、日志、钥匙牌的交互矩形不能与深渊碰撞重叠。当前数据没有 NPC 驻留钟楼，回归应验证全局 NPC 调度未被共享代码破坏，而不伪造 NPC。

## low-tide-cave

- 当前地图尺寸：920×520px。
- 当前有效可走面积：205,215px²。
- 当前空地比例：62%。不规则外轮廓存在，但内部是大而均匀的石地，视觉上仍接近矩形房间。
- 当前镜头缩放 / 玩家高度：1.00 / 48px。
- 主要视觉中心：名义上是右侧旧维护装置与底片路径，实际被暗度和尺度削弱。
- 次级视觉组：左侧洞口；下方积水与散落木板。
- 入口和出口：左侧 `cave_to_harbor`，来自港口的稳定出生点 (120,320)；入口和出口为同一洞口。
- 当前功能区：入口潮痕、中央维护通道、右侧设备/底片、下方水域；存在四类素材但没有自然咬合。
- 当前物件组合：入口框独立；维护设备、工具与底片未形成遮挡关系；木板漂在水域附近；岩块过小且散。
- 当前前景层：0。`cave_ceiling_foreground_set` 已在清单但没有生成实际洞顶。
- 当前光照结构：右侧设备暖光与中央极弱冷光；入口没有冷光，水面反光弱，整体可读性不足。
- 当前最大问题：一条平滑 42px 灰路横贯全图，岩壁没有决定路线，水体没有参与分割空间。
- 建议缩小比例：有效可走面积缩小 27%–31%，目标约 142,000–150,000px²；通过更深的岩壁侵入、水池和高差收紧，而不是矩形边框。
- 建议相机缩放：1.15，目标玩家约 55px 高，并保留入口到证物的导航全貌。
- 建议新增结构：复用 `cave_wall_*`、`cave_ceiling_foreground_set`、`cave_shallow_pool_set`、`cave_puddle_edge_set`、现有湿石/木板/设备；把维护路径改为石面—断板—泥地三段。
- 必须保留的交互与稳定 ID：`cave_negative_pickup`、`cave_inscription`、`cave_to_harbor`；低潮开放、停时、手电与底片跨循环逻辑；出生点 (120,320)。
- 视觉风险：岩壁图集色值接近地面，必须借边缘、入口冷光和前景剪影拉开；水面高光不能把深水误读为可走地。
- 功能风险：水域碰撞必须贴合不规则水体；断续维护路仍须连续可走；证物不能落在岩体或前景永久遮挡内。

## clock-basement

- 当前地图尺寸：900×560px。
- 当前有效可走面积：306,140px²。
- 当前空地比例：52%。中央台有体量，但外围仍是大地板上散列的小模块。
- 当前镜头缩放 / 玩家高度：1.00 / 48px。
- 主要视觉中心：中央协议台，当前是唯一成立但尚未连接外围系统的中心。
- 次级视觉组：左下红色清除机构；右下白色继续机构。三枚信号灯与七插槽没有形成稳定第三焦点。
- 入口和出口：下方中央 `basement_to_cabin`，来自维修舱的稳定出生点 (384,405)。
- 当前功能区：中央协议、七见证位、红白结局、信号监控、制动维护、入口。
- 当前物件组合：七插槽已经弧排但视觉尺度过小；信号灯浮在中央上方；红白装置与中心没有电缆/地槽；左右边缘只有零散齿轮和管件。
- 当前前景层：0。没有近景管道或柱体。
- 当前光照结构：中央暗金、红侧、白侧三光源存在，但环境太暗且插槽/信号灯没有层级光。
- 当前最大问题：808×500 的完整大房间承载量不足，机械组件之间没有可读的能量/信号连接。
- 建议缩小比例：有效可走面积缩小 29%–33%，目标约 205,000–217,000px²；用设备壁龛、放射地槽、后维护桥和侧边机械墙收紧。
- 建议相机缩放：1.15，目标玩家约 55px 高。
- 建议新增结构：复用 `basement_floor_cable_set`、`basement_wall_recess_set`、`basement_contact_shadow_set`、协议台/插槽/信号灯/红白装置；以放射地面结构、见证弧框、信号桥、侧站结构和前景管道建立统一系统。
- 必须保留的交互与稳定 ID：`three_signal_lights`、`witness_slot_seven`、`red_erase_lever`、`white_continue_knob`、`brake_interface`、`basement_to_cabin`；红/白结局条件、存档及跨循环字段；出生点 (384,405)。
- 视觉风险：过多电缆会变成噪声；红白光必须区分选择但不能抢走中央主焦点；七插槽状态需在 1152×648 下可辨。
- 功能风险：弧形插槽交互仍以稳定 ID 7 为剧情入口；白装置的显现必须继续受 `slot_seven_filled` 条件控制；入口主通道不能被中心台/前景管阻塞。

## 审计结论

四张图的工程基线为可运行、资源无报错、Portal 可达，但视觉均不通过本轮标准。共同根因不是资产数量，而是“有效空间过大 + 结构层缺失 + 功能簇关系弱 + 镜头 1.0 偏远 + 光源未分层”。实施阶段必须先改空间边界和主路径，再摆功能簇，最后处理前景与光照。
